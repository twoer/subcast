# 模型升级方案：Qwen3（LLM）+ SenseVoice（ASR 中英档）

基于 main 分支实施（已确认不依赖 feature/subcast-lite；其合并时 SenseVoice 的两个分发点再迁入 engine 抽象）。分两个独立可发版的阶段，先落盘方案文档 `docs/plans/2026-08-15-model-upgrade-qwen3-sensevoice.md`（按项目惯例），再按阶段实施。每阶段要求 `pnpm typecheck && pnpm lint && pnpm test:run` 全绿。

## Phase 1：Qwen2.5 → Qwen3（低风险先行，目标 0.5.0）

### 1.1 模型目录（shared/llmModels.ts）
- 档位 id 改为 `'4b' | '8b' | '14b'`（真实尺寸，避免「id 叫 3b 装 4B」的误导）：
  - `Qwen3-4B-Q4_K_M.gguf` ~2.6GB / 8GB RAM（替代 3B 档）
  - `Qwen3-8B-Q4_K_M.gguf` ~5.0GB / 16GB RAM（替代 7B 档）
  - `Qwen3-14B-Q4_K_M.gguf` ~9.0GB / 32GB RAM（不变）
- 下载源沿用 bartowski 双镜像（仓库名 `Qwen3-{N}B-GGUF`，无 Instruct 后缀；Q4_K_M 均为单文件，满足现有单文件下载器约束，实施时以实际资产为准）
- `RECOMMENDED_LLM_MODEL = '8b'`；`recommendLlmModel` 档位阈值不变

### 1.2 settings 一次性迁移
- `server/utils/settings.ts` loadSettings：旧值 `'3b'→'4b'`、`'7b'→'8b'` 映射（'14b' 不变）；Ollama 迁移正则同步支持 `qwen3:`
- `app/types/settings.ts` 类型同步

### 1.3 消除硬编码 id（6 处）
- `server/api/settings.put.ts:6`、`desktop/llm/status.get.ts:32`、`install.post.ts:37`、`[model].delete.ts:19`：改为从 `LLM_MODELS` 推导（shared 导出 `LLM_MODEL_IDS`）
- `desktop/modelManager/llmScan.ts:27`：FILENAME_RE → `/^Qwen3-(4B|8B|14B)-Q4_K_M\.gguf$/i`
- `desktop/modelManager/llmInstall.ts:192`：label → `"Qwen3 ${id}"`

### 1.4 thinking 模式适配（核心新逻辑，位置在 `server/utils/llmBackendLlamaServer.ts` + `llmServer.ts`）
- `llmServer.ts` spawn 参数加 `--ctx-size 16384`（当前默认 4096，摘要 maxTokens=4096 会溢出）
- chat 请求体加 `"chat_template_kwargs": {"enable_thinking": false}`（新版 llama-server 支持）
- 响应/流式解析：忽略 `reasoning_content` 字段；content 内 `<think>…</think>` 段统一在 backend 层剥离（`translate.ts`/`insights.ts` 的 JSON/markdown 解析零改动）
- 不做 `/no_think` 软开关（依赖升级后的 llama.cpp 字段支持 + 剥离兜底）

### 1.5 llama.cpp 升级（两处 pin 同步）
- `scripts/fetch-llama-server.mjs:31` 与 `.github/workflows/build-llama-server.yml:9`：`b4524` → 最新稳定 release（实施时查）
- 冒烟：新 llama-server 手动加载 Qwen3 GGUF，确认 `--version`、`chat_template_kwargs` 生效

### 1.6 UI / i18n
- `i18n/locales/*.json`：Qwen 2.5 → Qwen 3 文案
- `app/pages/setup-wizard/index.vue:60-63,79,239,243`：tier 列表/默认值/降级顺序改为 `['4b','8b','14b']`
- Models.vue 下拉已由目录驱动，无需改

### 1.7 测试
- `llmConfig/llmScan/llmInstall` 测试同步（文件名正则、尺寸单调、推荐档位）
- 新增：backend thinking 适配（请求体字段、reasoning_content 忽略、`<think>` 剥离、流式过滤）；settings 旧值迁移

## Phase 2：SenseVoice-Small 转写引擎（中英快档，按需下载）

### 2.1 最小引擎组装（不引入完整 engine 抽象；将来 lite 合并时迁入其 engine registry）
- `server/utils/settings.ts`：新增 `transcribeEngine?: 'whisper' | 'sensevoice'`（默认 `'whisper'`，JSON blob 加字段向后兼容）
- `transcribeQueue.runWorker`：按 engine 分发到 `transcribeChunk`（不动）或新 SenseVoice 路径
- `server/api/transcribe.get.ts:36-43`：readiness 按 engine 分支

### 2.2 推理模块（新 `server/utils/sensevoice/`，仿 diarize 模式）
- 常驻 worker（非 diarize 的一次性 worker——一个转写任务要推理几十段）：消息协议 `load / recognize(samples, offsetMs) / dispose`
- worker 源码字符串 + `createRequire` 加载 `sherpa-onnx-node`（已在依赖 ^1.13.2，nuxt.config external 已配）
- `sherpa.OfflineRecognizer` + `model.senseVoice` 配置，开 ITN（数字规整+标点）
- WAV 读取复用 `diarize/readWav.ts` 的 `readWavF32`（规避 sherpa readWave 的 NAPI external-buffer 问题）

### 2.3 时间戳对齐（设计核心）
- 复用 `detectSpeechSegments`（绝对 ms）+ `shared/chunking.ts` 的 `planChunksFromVad`，SenseVoice 路径用更小 cap（~10s，whisper 是 30s）
- 每段推理 → `Cue{ startMs: 段start, endMs: 段end, text: 识别文本 }`；段级 cue 对中短视频（VAD 段通常 2–8s）粒度可接受，段内细切留作后续迭代
- chunks 表 / original.vtt / meta.json / SSE 帧全部 engine 无关，直接复用

### 2.4 模型管理（按需下载，不动 electron-builder）
- `desktop/modelManager/senseVoiceConfig.ts`：sherpa-onnx GitHub release 资产（int8 量化 `model.int8.onnx` ~240MB + `tokens.txt`）+ gh-proxy 镜像 + size 校验
- 安装走现有 `downloader.ts`/`downloadRace.ts`；`shared/installContracts.ts` 扩展快照类型
- `server/utils/` readiness：文件存在 + 最小 size；`scripts/fetch-sensevoice.mjs` 供 dev 模式（仿 fetch-diarize-models.mjs，含 CN proxy）

### 2.5 UI
- Models.vue：转写引擎选择（Whisper / SenseVoice）+ SenseVoice 模型卡片（下载/删除/激活）
- `settings.put` 校验 `transcribeEngine` 合法值；`server/api/desktop/models.get.ts` 聚合返回

### 2.6 测试
- worker 源码与段→cue 映射纯函数单测；settings engine 字段校验；queue 分发用例（mock 两路）
- 真实模型中文音频冒烟（本地手跑对比 whisper-base/small，不进 CI——模型文件 gitignore）

## 风险与对策
- **llama.cpp 新版二进制兼容**：llama-server 是官方静态 zip，afterPack/rpath 只针对 whisper-cli，风险低；跑 `verify-mac-artifact.mjs` 确认
- **Qwen3 GGUF 单文件假设**：Q4_K_M 均 <10GB 单文件；实施时核对 bartowski 实际资产名
- **cue 粒度**：SenseVoice 段级 cue 比 whisper 词级粗，对长段（>10s）已用更小 VAD cap 缓解；精确时间轴导出用户仍可选 whisper
- **中文网络**：双镜像竞速与 gh-proxy 均沿用现有机制
