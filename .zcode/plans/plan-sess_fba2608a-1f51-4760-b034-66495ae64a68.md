# AI 转写润色（Qwen3）——设置 + 管线 + 播放器呈现

## 产品行为（默认开启，已确认）

- **设置 → 偏好设置** 新增「AI 转写润色」区块：
  - 开关卡片（照 debugMode 的 checkbox-card 样式）：默认开。文案：「转写完成后自动用本地 AI 润色：修正错别字、统一中英文写法、补全标点。原文保留，可随时切回。」未安装 AI 模型时禁用并提示「需先在 模型 页安装 AI 模型」。
  - 「专有名词提示」textarea（可选，≤500 字，placeholder 示例「如：庐州府学、布尔运算、主讲人名」）——实测这是纠错质量的关键杠杆。
- **自动链**：转写完成 → 若开关开且 LLM 已装 → 自动入队润色（批量任务流程自然继承）。
- **存量视频**：播放器字幕面板在「转写完成 + LLM 已配 + 无润色层」时显示「AI 润色」按钮，点击触发（SSE 进度，照翻译模式）。
- **播放器呈现**：ViewToggle 旁新增「原文 | 润色」分段控件，仅当 currentLang 为 original 且润色层存在/进行中显示；润色完成自动切到润色版，可一键切回（两层 cue 1:1 对应，切换零成本）。
- **导出**：润色层作为导出选项（ExportDialog 将 `polished` 显示为「润色版」）；双语导出（润色+译文）天然可用。

## 数据与后端

1. **设置字段**（`server/utils/settings.ts` + `app/types/settings.ts` 镜像，浅合并零迁移）：
   - `transcriptPolish: boolean`（DEFAULT true）
   - `polishHints: string`（DEFAULT ''）
2. **`server/api/settings.put.ts`**：boolean 守卫 + string 守卫（trim、>500 截断）。**顺手修一个现行 bug：`chunkingStrategy` 在此文件被静默丢弃**（前端发了后端不存），加同款校验。
3. **DB 迁移 v14**（`server/utils/db.ts`）：`polish_tasks(id, video_sha UNIQUE, status, model, progress_pct, error_msg, error_code, created_at, completed_at)`。
4. **`server/utils/polish.ts`**（新，照 translate.ts 的成熟模式）：`buildPolishMessages(cues, hints)`（system 用实测验证过的提示词 + 注入用户 hints；强调「只改文本、逐条对应、无法确定就保留原文」防过纠）+ `polishAll()`：25 cue 一批、严格 JSON 数组契约、**解析失败或数量不齐的批次回退原文**（保证与 original.vtt 的 cue 数/时间戳严格 1:1）。
5. **`server/utils/llmQueue.ts`**：出队查询加第三个 UNION 分支 + `ensurePolishTask(videoSha)` + `runPolishWorker`（读 `cache/<sha>/original.vtt` → polishAll → 写 `polished.vtt` + `subtitles` 行 `lang='polished', kind='polished'`）。
6. **`server/utils/transcribeQueue.ts`** 完成块（474-510 处 original.vtt 写入后）：开关开 && llmModel 已配 → `ensurePolishTask` + `tryStartNext`。
7. **`server/api/polish.get.ts`**（新，SSE shim 照 translate.get.ts）：手动触发 + 进度帧。
8. **`server/api/queue/list.get.ts`**：新增 kind='polish' 行（首页任务面板可见）。
9. **`server/api/cache/list.get.ts` + `useSubtitleStreams.loadCachedLangs`**：`polished` 不混入翻译语言下拉，仅作润色层存在标记。
